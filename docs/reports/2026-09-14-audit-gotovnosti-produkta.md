# SeoMarket: аудит готовности продукта

**Дата:** 14 сентября 2026
**Что проверено:** весь репозиторий (1120 файлов, 130 400 строк в `src`, 25 edge-функций,
36 миграций), боевой домен, GitHub Pages, зависимости.

---

## Вердикт

**Работает по-настоящему примерно треть продукта — но это правильная треть: ядро.**
Аудит сайта, скоринг, ИИ-оптимизация меты и (после ключей) трекинг позиций — настоящие.
Всё, что вокруг ядра — личный кабинет, админка, платежи, проекты — витрина с
зашитыми данными. Продажу продукта сегодня это не выдержит: клиент, который зайдёт в
кабинет, увидит чужие выдуманные сайты `example.com`, `mysite.ru`, `business.org`.

Часового механизма нет и в помине, но есть исправный двигатель: до «швейцарских часов»
не хватает не изобретений, а последовательной сборки корпуса вокруг готового ядра.

## 3. Чего нет вообще (а для SaaS обязано быть)

1. **Платежей нет как системы.** Ни Stripe, ни ЮKassa, ни таблиц заказов/подписок/счетов.
   Тарифы на сайте — картинка; купить нельзя.
2. **Нет сущности «проект/сайт».** Есть разовые задачи аудита (`audit_tasks`), но нет
   таблицы отслеживаемых сайтов. Из-за этого невозможны ни регулярные проверки, ни история
   по сайту, ни нормальный кабинет.
3. **Нет квот и лимитов.** Любой зарегистрированный пользователь может гонять аудиты
   и жечь ваши токены Anthropic без ограничений.
4. **Нет расписания проверок.** Позиции и аудит запускаются только руками; «ежедневный
   мониторинг» с сайта ничем не обеспечен (`pg_cron` используется только для уборки).
5. **Нет исправленной копии сайта.** ИИ возвращает улучшенные title/description, но
   собранной страницы не создаёт: таблица `fixed_pages` есть, сервер в неё не пишет.
   Обещание «скачать исправленный сайт» закрыто честной заглушкой (PR #4), но не выполнено.
   Локальные скрипты `scripts/` это умеют — в продукт они не заведены.

## 4. Технические долги

| Проблема | Риск | Что делать |
|---|---|---|
| **Домен `seomarket.ru` не ваш продукт.** Отдаёт постороннюю страницу с заголовком «seo продвижения», сервер nginx-reuseport — это не GitHub Pages | Продукта по адресу, который вы называете боевым, нет | Направить домен на Pages или на хостинг с приложением |
| **Публикация протухла.** Последний деплой Pages — 6 августа, **все три запуска workflow отменены** | На витрине версия полуторамесячной давности | Починить `deploy-pages.yml`, выкатить заново |
| **`report-generate` пишет в таблицу `pdf_reports`, которой нет в миграциях** | PDF-отчёты падают (или таблица создана руками в облаке и не зафиксирована в репозитории) | Проверить в Supabase, добавить миграцию |
| **9 edge-функций не описаны в `config.toml`** (`report-generate`, `send-email`, `generate-sitemap`, `health-check`, `issue-classifier` и др.) | Деплоятся с настройками по умолчанию — часть отвалится по JWT | Дописать секции |
| **Уязвимости в зависимостях:** 20 в боевых пакетах (1 критическая, 8 высоких), 138 по данным dependabot вместе с инструментами разработки (4 критические) | Безопасность | `npm audit fix`, критическую разобрать руками |
| **Бандл 2,1 МБ одним куском** (`vendor-other`) | Долгая первая загрузка | Разбить вендоров |
| **`.env` лежит в истории репозитория с ноября 2025** | Если там не только публичные `VITE_*` — утечка | Открыть файл, убедиться; при необходимости отозвать ключи |
| **6 edge-функций-сирот** (`issue-classifier`, `pdf-report-generate`, `health-check`, `generate-sitemap`, `blog-sitemap`, `cleanup-stuck-tasks`) | Мёртвый код или потерянная функциональность | Подключить или удалить |
| **Три PR висят открытыми** | Расхождение веток | PR #4 влить, PR #2 закрыть как перенесённый, по PR #1 принять решение |

## 5. План до «швейцарских часов»

### Этап 0 — запустить то, что уже сделано (1 день, без программирования)
1. Влить PR #4.
2. Вписать ключи поставщика выдачи в секреты Supabase (дешевле прочих XMLRiver).
3. `supabase db push` + `supabase functions deploy`.
4. Починить деплой Pages и выкатить свежую версию.
5. Решить вопрос с доменом `seomarket.ru`.

После этого продукт впервые честно делает то, что обещает на трёх главных экранах.

### Этап 1 — убрать обман (2–3 дня)
6. Кабинет посадить на реальные данные: обзор, отчёты, аналитика — из БД, как уже сделано в `/audits`.
7. Удалить или спрятать выдуманное: калькулятор PageRank, проверку уникальности, платежи в админке, подсистему прокси.
8. Убрать со страниц фич то, чего нет: анализ конкурентов, интеграцию с CMS, анализ скорости — либо в раздел «скоро», либо со страниц долой.

### Этап 2 — сделать SaaS SaaS-ом (1–2 недели)
9. Таблица проектов: пользователь добавляет сайт, к нему привязываются аудиты, позиции, отчёты.
10. Квоты: сколько аудитов и страниц в месяц на тариф, жёсткая проверка на сервере.
11. Расписание: еженедельный аудит и ежедневные позиции по проектам через `pg_cron`.
12. Платежи: ЮKassa для России, подписки, история счетов.

### Этап 3 — то, за что платят повторно (по мере сил)
13. Исправленная копия сайта на сервере (перенести логику из `scripts/` в edge-функции).
14. PageSpeed/Core Web Vitals в аудите.
15. Анализ конкурентов на том же SERP-провайдере, что и позиции — данные уже под рукой.
16. Уведомления в Telegram — таблицы уже есть.
